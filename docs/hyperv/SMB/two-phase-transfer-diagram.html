Component Configuration Where
SMB PV mount options multichannel,max_channels=8 kubevirt.go — PV mountOptions
Kernel SMB client rsize=4194304, wsize=4194304, bsize=1048576 Negotiated by mount.cifs on the OCP worker
Server-side Set-SmbServerConfiguration -EnableMultiChannel $true Hyper-V Windows host
Server interface advertisement Multiple NICs must be routable from OCP Check: Get-SmbServerNetworkInterface
qemu-img benefit Transparent — kernel stripes large sequential reads across channels No app-level changes needed; -t directsync bypasses write cache

How it works: The SMB PV is mounted by the kernel cifs driver with multichannel,max_channels=8. When the server advertises multiple network interfaces (via FSCTL_QUERY_NETWORK_INTERFACE_INFO), the kernel opens parallel TCP connections to each reachable interface. The qemu-img convert sequential reads are transparently distributed across these channels by the kernel, multiplying effective throughput beyond a single NIC's bandwidth. No changes to qemu-img or virt-v2v are needed — multichannel operates entirely at the kernel mount layer.

Prerequisite: The Hyper-V server must advertise multiple interfaces that are network-reachable from the OpenShift worker nodes. Cluster-only virtual adapters or unreachable interfaces will be negotiated but not used, limiting throughput to a single channel.
