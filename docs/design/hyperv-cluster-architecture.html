4. Data Model

Cluster

One per provider (cluster mode only). Holds the Windows Failover Cluster name and domain. Maps to model.Cluster.

Host

One per cluster node. State, CPU, memory from Get-ClusterNode. Maps to model.Host.

VM (cluster fields)

OwnerNode from Get-ClusterGroup. IsClusterRole marks HA-managed VMs. Host links to the parent Host record.

5. Provider Modes

Standalone (default)

managementType: standalone or empty

  • Single Hyper-V host
  • Per-VM GetDisks / GetNICs (original behavior)
  • No cluster, host, or tree endpoints
  • No Hosts tab in UI
Failover Cluster

managementType: cluster

  • Entry node inventories all cluster members
  • Batch disk/NIC collection per node
  • /clusters, /hosts, /tree/host REST endpoints
  • Hosts tab in UI shows node health
  • VM → OwnerNode mapping via Get-ClusterGroup

6. Key Design Decisions

Double-Hop Workaround

WinRM Kerberos delegation doesn't permit a second hop from the entry node to cluster members. RunOnNode wraps each command in Invoke-Command -ComputerName $node -Credential $cred using ConvertTo-SecureString -AsPlainText -Force, bypassing the limitation without requiring CredSSP configuration.

Batch PowerShell Scripts

BatchGetVMHardware iterates all VMs on a node in one script, collecting security, checkpoint, disk topology + capacity + RCT, and NIC info. BatchGetVMGuest collects guest OS and network config for running VMs. Two scripts × N nodes instead of many scripts × N VMs.

Graceful Fallback

If a batch call fails for a node, fallbackPerVMDetails falls back to per-VM RunOnNode calls for just that node's VMs. Other nodes' batch results are unaffected. Standalone mode is completely unchanged.

7. SMB Path Mapping (Cluster Mode)

In cluster mode, a VM's disk path may be either a local path (e.g. C:\Hyper-V\Virtual_Hard_Disks\vm.vhdx) or a UNC path (e.g. \\SERVER\ShareName\vm.vhdx) when disks reside on a remote SMB share. mapWindowsPathToSMB handles both cases to produce the mount-relative path that virt-v2v uses to access the disk.

UNC Matching

The UNC handler compares the share name from the path with the share name extracted from the provider's SMB URL — it does not compare server hostnames, which may differ between hostname and IP. A case-insensitive match on the share name is sufficient since all cluster nodes reference the same share.

8. Per-Host Migration Scheduler

The Hyper-V scheduler tracks in-flight migrations per source host, preventing a single node from being overloaded while allowing parallel migrations from different nodes.

Scheduler Details
  • Cost per VM: 1 (unlike vSphere which uses per-disk cost for CDI). Hyper-V uses virt-v2v (SMB) or populator (iSCSI), both per-VM.
  • MaxInFlight: applies per host, not globally.
  • Standalone mode: all VMs map to a single empty host key, preserving the original global counter behavior.
  • PowerOff routing: in cluster mode, Stop-VM is routed to the correct node via RunOnNode using the VM's OwnerNode.
  • MaintenanceMode: checks the host's state — blocks migration if the node is Paused or Down.
